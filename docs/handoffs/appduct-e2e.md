## Changes

- Added tester-army `e2e` with its mobile engine and Appduct 0.14.0.
- Three deterministic tests cover Pulse, Settings/back, and restart persistence.
  Each starts with cleared disposable app data, calls the existing root actor's
  onboarding event through Appduct, proves repeated calls are safe, and restores
  the committed synthetic archive through the native transaction.
- Tool registration and bootstrap require both development mode and the E2E
  environment flag. Metro resolves its upstream asynchronous configuration
  before applying Appduct's stripping resolver; a three-case regression test
  protects this composition and retains the asset registry.
- `.oxlintrc.json` excludes only `.opencode/plugins/entire.ts`, generated by
  Entire's `enable` command. This clears the full verification failure without
  weakening application architecture rules or editing generated vendor code.
- Harness supports an explicit simulator name/runtime while preserving defaults.

## Local setup findings

Normal Metro excludes `__tests__`; the host test runner therefore sends the
committed archive over Appduct rather than importing it into the app bundle.
Effect Schema validates the archive at the app boundary. Native Harness loads
its test fixture directly.

The host's default Node 22.22.0 does not meet e2e's engine requirement. Native
E2E verification used Node 24.19.0. Use the version prerequisites in the guide.
The tests conditionally accept the iOS deep-link Open confirmation through its
accessibility locator; absent alerts do not fail setup.

The default Appduct port was occupied. Verification used an isolated task-owned
state directory with `wssPort: 0`; the user's daemon policy was not changed.
Expo's fingerprint loader also recursively spawned processes; the scoped local
build workaround is documented in the guide. All task-owned build processes
were stopped; unrelated processes and dirty repository files were preserved.

No remote push or publication was requested. No user-only blocker remains for
the delivered test setup. Both platforms use dedicated disposable devices.

## Android execution follow-up

The Android Debug APK compiled with Appduct (`751` Gradle tasks, successful).
Argent's streaming install aborted and left pending installs scoped to the new
emulator. After stopping those exact ADB children, a non-streaming install
succeeded. The first launch then stalled; a scoped cold boot recovered after
removing only this task's emulator snapshot. No existing emulator or physical
phone was reset. All E2E assertions passed after correcting the developer-menu
setup and waiting for tool publication. These failures were setup evidence,
not passing app tests.
